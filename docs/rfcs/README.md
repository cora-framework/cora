# CORA RFCs

Substantial changes - new modules, public API changes, architectural shifts - start life as an RFC so design happens in the open before code.

## Process

1. Copy `0000-template.md` to `NNNN-short-title.md` (next free number).
2. Open a PR. Discussion happens on the PR.
3. The core team accepts (merge), postpones, or declines (close with reasoning).
4. Accepted RFCs are implementation-ready; tasks reference the RFC number.
